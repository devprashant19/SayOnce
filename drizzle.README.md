# Migrations

Generated by drizzle-kit from `lib/db/schema.ts`:

```bash
npm run db:generate   # writes drizzle/NNNN_*.sql
npm run db:migrate    # applies them to DATABASE_URL
```

## The one migration you must write by hand

`trail_entries` is append-only, and the hash chain is only a guarantee if the
database enforces that rather than the application remembering to. After the
first generated migration, add `drizzle/0001_trail_append_only.sql`:

```sql
-- The Trust Trail is append-only. A correction is a new row, never an edit.
REVOKE UPDATE, DELETE ON trail_entries FROM PUBLIC;
CREATE RULE trail_no_update AS ON UPDATE TO trail_entries DO INSTEAD NOTHING;
CREATE RULE trail_no_delete AS ON DELETE TO trail_entries DO INSTEAD NOTHING;
```

Phase 4's tamper test deliberately defeats this by editing a row as the table
owner. That is the point: the test proves "Verify trail" turns red at exactly
the altered row, which is what makes the badge mean something.
